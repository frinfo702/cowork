# playbook: implementation — 実装・再現実装

## 目的

動く最小構成から始め、正しさを段階的に確認しながら実装する。論文の数値と一致しないまま大規模化しない。

## 手順

1. 仕様を確定する。入力、出力、モデル、損失、最適化、データ。論文の該当箇所と公式実装の有無を確認する。
2. 最小構成を作る。小さなデータ、小さいモデル、1 step が通ることを先に確認する。
3. 部品ごとに検証する。データローダ、前処理、モデルの形、損失、勾配。既知の入力で期待値を確認する (`skills/reproducibility-checklist`)。
4. overfit テストを行う。数サンプルに過学習できるか。できなければ実装かデータを疑う。
5. 公式実装と比較する。再現実装の場合、中間テンソルや 1 step の数値を突き合わせる。
6. スケールする。学習率、バッチサイズ、勾配蓄積、混合精度、分散。変更は 1 つずつ。
7. 記録する。commit、環境、config、seed、コマンドを `data/experiments/` に残す。
8. よくある失敗を確認する (`skills/reproducibility-checklist`): データリーク、前処理の不一致、評価モードの切り忘れ、seed 未固定、正規化の違い。

## 使う skills

- `skills/reproducibility-checklist`
- `skills/experiment-methodology`

## 出力

- 実装と設定ファイル
- 検証記録 (どの部品をどう確認したか)
- 公式実装との差分
- 再現手順 (コマンド、環境、seed)

## 承認・エスカレーション

`approval: none`。実験の実行と計算資源の消費はユーザーの環境で。外部 API やクラウドにデータを送る前に確認する。
