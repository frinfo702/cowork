# 実験方法論

## 基本原則

1. 結果を見る前に仮説と成功条件を固定する。後付けの解釈をしない。
2. baseline は強いものを選ぶ。弱い baseline との比較は意味がない。
3. 計算量を揃えて比較する。同じ GPU 時間、同じデータ量、同じチューニング努力。
4. test セットで探索しない。探索は train/val で、最終評価は一度だけ。
5. 単一 run で結論を出さない。最低 3 seed、可能なら 5 seed。

## 統計の基本

- 平均だけでなく標準偏差・中央値・信頼区間を報告する。
- 差の報告は効果量 (Cohen's d、相対改善率) と不確実性をセットで。
- 検定はデータの構造に合わせる (対応のある/ない、ノンパラメトリック)。
- 多重比較は補正する (Bonferroni、Holm、FDR)。探索的結果と確認的結果を分ける。
- p 値は「効果がないとは言えない」以上の意味を持たせない。有意でない差を「傾向」と言い換えない。

## Ablation

- 変更は 1 要素ずつ。交互作用が疑われる場合は要因計画を組む。
- 各要素の寄与を、追加コストと合わせて示す。
- 効かない要素を正直に報告する。

## よくある落とし穴

- データリーク、前処理の train/test 混入
- ハイパーパラメータの test での選択
- 計算量の不公平 (提案手法だけ長く学習)
- seed 選択によるチェリーピッキング
- 評価指標の定義変更 (結果を見た後)
- 学習率スケジュールなど、比較対象で設定が揃っていない

## 記録

すべての run について、commit、環境、config、seed、コマンド、結果を保存する。失敗 run も残す。`data/experiments/` に 1 run 1 ファイル。
