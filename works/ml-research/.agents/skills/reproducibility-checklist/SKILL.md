# 再現性チェックリスト

## 実験を実行する前に

- [ ] コードの commit を記録した
- [ ] 環境を固定した (Python、CUDA、主要ライブラリのバージョン)
- [ ] データの版・取得日・前処理手順を記録した
- [ ] seed を固定し、seed のリストを決めた
- [ ] config をファイルで管理した (コマンドライン引数のコピペではなく)
- [ ] 計算資源と予想所要時間を記録した

## 実行中

- [ ] 損失・指標・勾配ノルムをログに残した
- [ ] 失敗 run と中断 run も保存した
- [ ] 評価は test で一度だけ行った
- [ ] 中間チェックポイントを保存した

## 報告する前に

- [ ] seed 間のばらつき (平均 ± 標準偏差、n) を報告した
- [ ] データ分割、前処理、評価指標の定義を書いた
- [ ] baseline の設定とチューニング範囲を書いた
- [ ] ハイパーパラメータの探索方法と範囲を書いた
- [ ] 計算資源 (GPU 時間、パラメータ数) を書いた
- [ ] 限界と、再現しなかった事項を書いた
- [ ] コードと設定の公開方法を決めた

## ML Reproducibility Checklist との対応

NeurIPS などの投稿では、公式の Reproducibility Checklist への回答が求められる。項目は、コード、データ、ハイパーパラメータ、評価、計算、乱数、統計の各面をカバーする。投稿先の最新版を確認して従う。

## よくある再現性の穴

- seed は固定したが cuDNN の非決定性を残した
- データの前処理を notebook で手動実行した
- 評価スクリプトの版が論文と違う
- チェックポイントの選択基準が不明
- 計算資源の差 (バッチサイズ、学習ステップ数) を書いていない
